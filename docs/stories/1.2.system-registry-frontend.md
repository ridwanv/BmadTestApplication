## Story
**As a** System Owner/Architect,
**I want** a complete user interface for managing systems with forms, detailed views, filtering, and bulk operations,
**so that** I can efficiently manage the system registry through an intuitive web interface that supports all CRUD operations and system relationships.

## Acceptance Criteria
1. System owners can create new systems using a comprehensive form with validation
2. System owners can edit existing systems with pre-populated forms and validation
3. System owners can view detailed system information across multiple tabs (Overview, Attributes, Dependencies, History, Ownership)
4. System owners can filter and search systems using multiple criteria
5. System owners can perform bulk operations on selected systems
6. System owners can delete systems with confirmation dialogs
7. System owners can manage hierarchical relationships (system → subsystem) through the interface
8. All forms provide real-time validation feedback and error handling
9. System list supports advanced sorting, pagination, and column management
10. Interface follows enterprise UX patterns with responsive design

## Dev Notes

### Frontend Architecture Requirements
**Component Structure** [Source: architecture/frontend-and-ux-architecture.md#component-tree]:
- Systems List Page → Enhanced DataGrid with filters, bulk actions, search
- System Details Page → Tabs: Overview, Attributes, Dependencies, History, Ownership  
- Create/Edit System Forms → Comprehensive forms with validation
- Confirmation Dialogs → Delete, bulk operations with impact assessment

### Technical Requirements
**Technology Stack** [Source: architecture/solution-overview.md]:
- Frontend: Blazor Server with MudBlazor components
- Validation: Client-side FluentValidation integration
- State Management: Component state with efficient re-rendering
- Pattern: MVVM with proper separation of concerns

### UI Component Specifications
**Required MudBlazor Components**:
- MudDataGrid (enhanced from Story 1.1)
- MudForm with MudTextField, MudSelect, MudAutocomplete
- MudTabs for detail views
- MudDialog for confirmations and modals
- MudSnackbar for notifications
- MudMenu for bulk operations

### Integration Points
**Backend Integration** [Source: Story 1.1]:
- Uses existing SystemsWithPaginationQuery for data loading
- Uses existing CreateSystemCommand, UpdateSystemCommand, DeleteSystemCommand
- Integrates with GetSystemByIdQuery for detail views
- Leverages existing validation and caching infrastructure

### Form Field Requirements
**System Form Fields** [Source: architecture/data-architecture.md#core-tables]:
- Name (required, text input)
- Description (required, multiline text)
- Category (required, dropdown)
- Type (required, dropdown)  
- CotsCustom (required, radio buttons)
- HostingCurrent (required, dropdown)
- HostingTarget (required, dropdown)
- InsourceOutsource (required, radio buttons)
- Status (dropdown, default Active)
- Owner assignment (user selector)

### File Locations

### Validation Integration
**Client-Side Validation**:
- Integrate with existing FluentValidation rules from backend
- Provide real-time validation feedback
- Display validation errors clearly with field highlighting
- Support form dirty state tracking

### UX Patterns
**Enterprise UX Requirements** [Source: architecture/frontend-and-ux-architecture.md#additional-ux-considerations]:
- Consistent loading states across all operations
- Clear success/error feedback for all actions
- Responsive design for different screen sizes
- Keyboard navigation support
