# Story 1.1: System Registry CRUD

<!-- Powered by BMAD™ Core -->

## Status
Review

## Story
**As a** System Owner/Architect,
**I want** to create, read, update, and delete systems in the system registry,
**so that** I can maintain a central catalog of all systems with unique identifiers and basic hierarchical organization.

## Acceptance Criteria
1. System owners can create new system records with required fields (Name, Description, Category, Type)
2. System owners can view existing system records in a searchable/filterable list
3. System owners can update system information they own
4. System owners can delete systems they own (with confirmation)
5. All system operations are logged for audit purposes
6. System records support hierarchical relationships (system → subsystem)
7. System records include core attributes: CotsCustom, HostingCurrent, HostingTarget, InsourceOutsource
8. System creation/updates validate required fields and data types
