## Story
**As an** Architect,
**I want to** update or deactivate an attribute definition,
**so that** I can maintain and manage the lifecycle of system attributes while preserving data integrity.

## Acceptance Criteria
- Given an existing attribute
  When I change rules or deactivate
  Then changes apply to new edits and UI shows impact

## Dev Notes
[Source: docs/architecture/data-architecture.md]
- Work with AttributeDefinitions table:
  - Key fields: Id PK, Name, DataType, IsMandatory, AllowedValuesJson, Regex, Category, IsActive
  - Use SystemAttributeValues table to check for existing values
  - ChangeLogs table tracks all modifications

[Source: docs/prd/technical-architecture-considerations.md]
- Follow REST API patterns via Azure API Management
- Use Key Vault for sensitive operations
- Implement RBAC checks
- Ensure audit trail integration with Azure Log Analytics

Previous Story (B1.1) Technical Decisions:
- AttributeDefinition extends BaseAuditableEntity
- Uses AuditableEntityInterceptor for change tracking
- Validation rules integrated at both API and UI layers

Implementation Notes:
- Edit operations must preserve existing attribute values
- Deactivation should be a soft delete
- Impact analysis must scan all SystemAttributeValues
- Changes must be versioned for audit compliance
